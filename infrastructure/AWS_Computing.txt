#AWS
##サーバーとは
AWSに限らず、あらゆるシステムでも欠かすことが出来ないのがシステム処理をするコンピュータである。
ネットワーク上でデータヤサービスのECSなど、幅広いコンピューティングサービスが提供されている。
サービスを提供するコンピュータをサーバー、そのサービスを利用するプログラムをクライアントという。
webサイト、オンラインゲーム、SNS、メールなどでもそれぞれのサーバーが存在する。

##主なサーバーの種類
#webサーバー
webページ事態の構造を作成するHTMLファイルやデザインを定義するCSSファイル、サイトに表示される画像ファイルなど、サービス提供に必要なデータが保存されている。
サーバーのOSには主にLinuxやWindowws Serverが採用される。

#DBサーバー
システムが取り扱うデータを一元管理するデータベース管理システムが導入されているサーバーのことをDBサーバーという。データの保存や更新、バックアップ等の管理機能やデータ検索を行うデータ処理機能は共通している。

#メールサーバー
SMTPプロトコル、POP3プロトコルを利用してメール送信や輸送、受診を行うサーバーのことをメールサーバーという。

##サーバーの仮想化
通常、サーバーなどのハードウェア1台につき、１つのOSが大前提となるが、サーバーの仮想化を行うことで１つのハードウェア上で複数のOSを稼働させることができる。
AWSでも花王sか技術は多く使われている。代表的なものはAmazon Elastic Compute Cloud (Amazon EC2)サービスである。EC2ではAWSの大規模ﾅｻｰﾊﾞｰでこの仮想化が行われている。ユーザーは自分の用途に応じてOSの種類やCPU、メモリの大きさを自由に選択し、インスタンス(仮想サーバー)を作成することになる。

#Amazon EC2サービス
Amazon elastic Compute Cloud (EC2)は仮想サーバを簡単に作成できるサービスのこと。
OSはAWSが用意しているものから選択できる。CPUやメモリ、サーバーナドノスペックも利用者が自由に選択できる。変更や削除が容易に行える。
EC2ではカソウサーバをインスタンスという単位で管理する。サーバー稼働時間に対して従量課金で料金が発生する。
「Amazonnマシンイメージ(AMI)」はOSやソフトウェアの設定が入ったテンプレートである。

##インスタンスタイプのネーミング
例：m6g.medium
m…ファミリー…メモリ重視やCPU重視など特徴ごとに文字列がある。
6…世代…数が大きいほど新しく高性能
g…Graviton2(CPUの名前)のg,ネットワーク強化のnなど、いろいろな種類がある。追加機能文字が無いタイプもある。
medium…サイズが大きいほど高性能。値段もサイズが大きいほど高価。

###EC2インスタンスのファミリー
T…バースト可能な汎用タイプ
M…バランスのとれた汎用タイプ
C…コンピューティング最適化(vCPU数が多い)
R…メモリ最適化(メモリ搭載量が多い)
P…高速コンピューティング
I…ストレージ最適化

T系インスタンスについてはベースラインと呼ばれる決められたCPU使用率が定義されていて、それを超えて(バーストして)利用が可能。

##仮想サーバーの外部公開
EC2上で構築したwebアプリケーションを公開する場合、設定を追加する必要がある。
EC2をパブリックサブネットに配置する、パブリックIPアドレスをEC2に付与する、セキュリティグループで外部からのアクセスを許可する、
以上の3点の条件を満たす必要がある。

##アクセス制御
どこからどこまでに対してアクセスを許可するかといったEC2のアクセス制御にはセキュリティグループを使用する。オンプレミスではファイアウォールという機器を使用してシステムへのアクセス制御を行うが、セキュリティグループは仮想ファイアウォール機能。
EC2への通信をインバウンドルール、EC2から外部への通信をアウトバウンドルールという形式で指定する。
どちらも通信を許可するネットワークとポート番号を指定する。ポート番号は使用する通信の種類で決まる。たとえばLinuxを操作するSSHは22番ポート、Webアクセスを行うHTTPは80番になる。
##セキュリティグループ
設定できるルールは許可のみ。特定のネットワークから通信を拒否する設定はできない。
ネットワークACL(アクセスコントロールリスト)やその他のアクセス制御機能が有るため、拒否設定を行う場合はそれを利用する。

#負荷に応じてサーバーを追加、削除する
Amazon EC2 Auto Scaling (Auto Scaling)という機能を使用すると、サーバーの複製追加と削除を孵化状況に応じて自動実行できる。サーバーを追加することをスケールアウト、削除することをスケールインと呼ぶ。
サーバー負荷の指標としてCPU使用率が挙げられる。その使用率に応じてサーバー追加処理（スケールアウト）が可能。
##ターゲット追跡スケーリングという指定した値に近づくようにサーバー数を自動設定する機能もある。Auto Scalingの利用自体は無料で、稼働しているEC2インスタンスの料金が発生する。
Auto Scalingは障害に強い利点がある。指定された台数を維持するという機能の為、サーバーに障害があって停止した場合はAuto Scalingの機能によりサーバーが自動的に再生成される。
その他、予測スケーリング機能やバージョン管理など多くの機能を持っている。

#サーバーを持たずにプログラムを実行する
##AWS Lambda (Lambda)
AWS Lambda (Lambda)はサーバーレスコンピューティングサービスのこと。OSなどのインフラストラクチャの管理が不要で、利用者はプログラムコードを準備し、Lambdaにアップロードするだけで実行できる。
"サーバーレス"となっているが、本当にサーバーが無いのではなく、AWS側で実行基盤が管理されるため、利用者の管理するサーバーが無いという意味になる。利用者はインフラ部分の管理をAWSに任せられる為、ビジネスロジックに関わるコード開発に集中できる。

###Lambdaの利点
セキュリティ…OSなどのインフラのパッチ適用など、実行基盤のセキュリティはＡＷＳで管理され、利用者は自分が書いたコードのみ責任を持って開すればよい為、簡単にセキュアな実行環境を実現できる。

コスト…Lambdaではコードが実行される時間1ミリ秒ごとに課金される。EC2では、たとえ処理が行われていなくても起動している時間分料金が発生する。Lambdaでは実行していない時間は料金が発生しない為、コスト削減につながる。

可用性…AWSには複数の物理的に独立したアベイラリティゾーン(AZ)があるが、LambdaではAWS管理のもと複数のAZに渡って関数が実行される。例えば１回目はAZ-Aで実行され、２回目はAZ-Cで実行される、という事が起きる。
AZ障害時は実行可能なAZで実行される。利用者が意識しなくても高可用性、耐障害性が保たれている。

拡張性…Lambdaは複数の処理を受けると自動的にAWSが管理する処理用のインスタンスが立ち上がり、自動拡張される。

##EC2のLambdaと比べたメリット
・オンプレミス上のアプリケーションをAWSへ移行する場合、EC2ではOS設定などをそのまま移行しやすい
・EC2はインスタンスタイプやOS,ネットワークなどを自由に設定できるという柔軟性がある。
・大量のトラフィックやアクセスを常時処理する場合、EC2のほうが安くなる場合もある。
・EC2ではサーバーにプログラムをデプロイ(配置)するという従来の方式で開発を進められる。LambdaにはAWS独自の設定方法や開発方法があるため、初学者にはやや難しい。

##関数を作成して実行する
Lambdaでは、関数という単位でプログラムコードを管理し、処理も関数単位で実行する。
関数の作成は複数のツールから可能で、AWSマネジメントコンソールの画面上からも作成できる。

#コンテナの仕組みと特徴
コンテナとは、仮想サーバーをマンションに例えるならシェアハウスのようなもの。
コンテナを起動するときどのようなアプリケーションプロセスで起動するかをあらかじめ定義したベースファイルをもとにして起動する。これをコンテナイメージという。コンテナイメージからコンテナを複数起動することができる。
コンテナは仮想化と比べて軽量で高速、起動が速い、というメリットがある。軽量である理由は コンテナ内に含まれるものが少ないことが挙げられる。
仮想サーバーはが起動する際はOS,ミドルウェア、アプリといったものが必要になる。その為、仮想サーバーを起動する際に指定する仮想サーバーイメージにはこれらのファイル群はパッケージされている。一方でコンテナではアプリプロセスのみが起動する。

##コンテナのデリバリー性
「システム環境への反映のし易さ」という意味でコンテナはデリバリー性に優れている。
コンテナはコンテナイメージを作成しておくと、どのサーバー環境においてもコンテナランタイムさえインストールしておけばコンテナイメージで定義したアプリケーションプロセスを実行できる。ローカルのパソコンで起動していたコンテナをそのまま本番環境や開発環境などさまざまな環境でも同じように起動できる。これによってアプリケーションプロセスの再現性が高くなり、複数のシステム環境で動かす場合でも環境による差異を少なくできる。
コンテナイメージはレジストリというイメージ管理ツールを用いてイメージごとにレポジトリという単位で管理することが可能。レジストリを経由することでコンテナイメージを複数のシステム環境に対して容易に展開することが可能。
高速でデリバリーしやすいことは開発がスムーズになりやすくなることに繋がる。
一方、コンテナランタイムはサーバー側でOS上で起動するため、同じサーバー上で起動するコンテナは異なるOSを利用することができません。
コンテナは基本的に揮発性で、コンテナが削除されるとコンテナ内に保存されているデータも一緒に削除される。
そのため、OSに依存したり、処理するデータを保持しなければならない設計になっているアプリケーションはコンテナの利用には不向き。

##コンテナオーケストレーション
コンテナオーケストレーションツールでは、コンテナが異常終了した時、システム側に負荷が増えた時、コンテナを何台追加で起動するのか、どの程度負荷が増えた場合にコンテナを追加するのか、などの管理を自動化することができる。
