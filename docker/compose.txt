\### Dockerとは
Dockerは、コンテナ技術を利用してアプリケーションを効率的にデプロイ、スケール、および管理するためのプラットフォーム。Dockerは、ソフトウェアを「コンテナ」と呼ばれる独立したユニットにパッケージ化します。このコンテナは、アプリケーションコード、ランタイム、ライブラリ、および依存関係をすべて含んでおり、どの環境でも一貫して動作する。
効率的なデプロイ、スケーラビリティを確保することが容易になる。

##コンテナ
OSを動かす独立したサーバー仮想環境。それを個人で構築する。
Dockerイメージを元に作成される仮想環境のこと。

##イメージ
厳密にはDockerの用語ではない。
簡単にいうと、OSやアプリを使うために必要な一式が格納されているファイルのことを指す。
Dockerの文脈で言うと「コンテナイメージ」と言われ、コンテナを起動するために必要な一式が格納されているファイルのことを指す。

##Docker file
イメージを作成するための設計図。

Dockerfileを専用コマンドにて組み立てる（buildする）ことで、Dockerイメージが作成されるのです。そうしてDockerイメージを実行する（runする）ことによって、Dockerコンテナが作成される。

###Dockerfileで使用される主なコマンド

FROM：ベースイメージを指定する。すべてのDockerfileの最初に記述する必須命令。
WORKDIR：以降の命令を実行する作業ディレクトリを設定する。
COPY：ホストマシンのファイルをコンテナ内にコピーする。
RUN：イメージのビルド時にコマンドを実行しする。パッケージのインストールなどに使う。
CMD：コンテナ起動時に実行するデフォルトコマンドを指定する。
EXPOSE：コンテナが使用するポート番号を明示する。
ENV：環境変数を設定する。

例
FROM php:7.4-apache
RUN apt-get update && apt-get install -y vim zip unzip
RUN a2enmod rewrite
EXPOSE 80
CMD ["apache2-foreground"]

##docker compose（ドッカーコンポーズ）
公式ドキュメントより
"Docker Compose とは、複数コンテナのアプリケーションを定義・共有するために役立つように、開発されたツールです。Compose があれば、サービスを定義する YAML ファイルを作成し、コマンドを１つ実行するだけで、瞬時にすべて立ち上げたり、すべてを削除したりできます。"

##流れの具体例
docker hub（正確にはそれ以外のリポジトリでも可能）からベースコンテナのイメージをダウンロード（docker pull）。
ローカルPC内に持って来れたらそのイメージと自分で作ったDockerfileを合わせて独自のイメージを作成（docker build もしくは docker compose build）。
独自のイメージをコンテナとして起動する（docker run もしくは docker compose up）。


##Dockerhub を使用している中でよくあるエラー
###service "web" is not running エラー(dockerのコンテナの一つが勝手に止まってしまう等)
これは docker compose exec web ... や docker compose logs web をしようとしたときに、web コンテナが起動していない状態で出るエラー。
原因は以下である事が多い：
- docker compose up をまだしていない
- docker compose up はしたけど、コンテナがすぐ停止してしまった（アプリ起動エラーや依存サービス未起動）
- 名前が web ではない

*対処手順*
まずコンテナの状態を確認

\docker compose ps
web が Up になっているか確認
もし Exit 状態ならログを確認
Exit 0 → 正常終了（スクリプトが終わっただけ）
Exit 1 や Exit 137 → エラー終了や強制終了


\docker compose logs <サービス名>
アプリケーションが起動できない原因が出てくる（例: gem不足、DB未接続、設定ミス）
起動していないなら、まず立ち上げる
RailsアプリならエラーメッセージやGem不足が出る
NodeやPythonアプリも同様にスタックトレースが出る

終了コードを直接確認
docker inspect <コンテナID> --format='{{.State.ExitCode}}'
0 → 正常終了
1〜 → エラーコード


\docker compose up --build
"--build" を付けると Dockerfile の変更も反映される。

###コンテナの状態確認
\docker compose ps
web のステータスが Exit か Up かを確認する。

###ログ確認（原因特定）
\docker compose logs web


##よくある Rails 初学者環境でのエラー例
cannot load such file -- mysql2
→ Gemfile に mysql2 が無い or bundle install 未実行
Access denied for user 'root'@'xxx'
→ database.yml の username / password が db コンテナの設定と一致していない
Can't connect to MySQL server on 'db' (111)
→ DBコンテナは起動してるが、接続待機中のうちに Rails が落ちた
