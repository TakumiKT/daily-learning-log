#COBOL
##COBOLとは
COBOLとは、1959年にアメリカで生まれた事務処理用に開発されたプログラミング言語。
COBOL(Common Business Oriented Language)の意味で、「事務処理用の高級言語」として開発された。

##特徴
1.COBOLの大きな特徴として「事務処理用のプログラムを効率よく開発できる」ことが挙げらる。
2.人間の言葉に近い文法でプログラムを記述できるため、習得が容易でプログラミングの入門にも最適。
3.単純な順ファイルから、相対・牽引ファイルなど、さまざまなファイルを扱う機能が提供されている。
4.ファイルに大量のデータを書き込んだり、ソートやマージしてデータを並べ替えるといった作業を、高速で処理することが可能。
5.事務処理で必要な帳票の作成や印刷などの処理が可能。
6.データを10進数で表現できるため、金額や各種データの確認が容易に行うことができる。
7.COBOLは、WindowsやUnix/Linuxなど、さまざまなコンピュータで利用できるため、移植性が極めて高い言語。
8.歴史が古く安定した言語で堅牢性に優れており、信頼性が高いと言えます。そのため、大規模なシステムの開発でよく使用される。

##プログラムの書き方
COBOLは、大きく分けて4つの部で構成されている。それぞれの部は「見出し」がある。

プログラムは「見出し部（IDENTIFICATION DIVISION）」から始まり、「環境部（ENVIRONMENT DIVISION.）」、「データ部（DATA DIVISION）」「手続き部（PROCEDURE DIVISION）」と処理を順に記述していく。

見出し部以外は省略することが可能で、部（DIVISION）の中にはいくつかの節（SECTION）や段落がる。

###見出し部（IDENTIFICATION DIVISION）
見出し部はCOBOLプログラムを識別するための部で、見出し部のみ節は無い。PROGRAM-IDには作成するプログラム名などの情報を記述する。

\IDENTIFICATION DIVISION.
\PROGRAM-ID. [プログラム名など].

###環境部（ENVIRONMENT DIVISION）
環境部はプログラムを適用するコンピュータ名や、環境変数などの情報の定義を行う構成節（CONFIGURATION SECTION）と、プログラムファイルを使用する場合に記述する入出力節（INPUT-OUTPUT SECTION）がある。

\ENVIRONMENT DIVISION.
\CONFIGURATION SECTION.
\INPUT-OUTPUT SECTION.
\FILE-CONTROL.
\SELECT ファイル項目 ASSIGN TO 'ファイル名'

###データ部（DATA DIVISION）
データ部はファイル節（FILE SECTION）、作業場所節（WORKNG-STORAGE SECTION）、連絡節（LINKAGE SECTION）、通信節（COMMUNICATION SECTION）などから構成される。主にプログラムで使用するデータ項目やファイルのレコードの宣言を行う。

\DATA DIVISION.
\FILE SECTION.
\FD ファイル項目.
\01 ファイルレコード.
\05 データ項目1 PIC 9(5).
\05 データ項目2 PIC X(3).

###手続き部（PROCEDURE DIVISION）
手続き部では主に各種処理を宣言したり、実行される手続きやエラーになった場合の処理内容を記述する。
また、STOP文を記述すれば、プログラムを終了することができる。

\PROCEDURE DIVISION.
\MAIN SECTION.
 
実行処理...
 
\STOP RUN.

##ChatGPTによるローカルでの実行について解説

       IDENTIFICATION DIVISION.
       PROGRAM-ID. HELLO.

       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-NAME PIC X(20).

       PROCEDURE DIVISION.
           DISPLAY "INPUT YOUR NAME: " WITH NO ADVANCING
           ACCEPT WS-NAME
           DISPLAY "HELLO, " WS-NAME
           STOP RUN.

行の先頭に空白が入っているのは、固定形式で書いているためです。
GnuCOBOLの固定形式では、基本的に次のように列の役割が決まります。

1～6列目   行番号などの領域
7列目      コメントや継続を表す領域
8～72列目  COBOLのプログラムを書く領域

GnuCOBOLは固定形式を標準で扱い、--fixedまたは-fformat=fixedでも明示できます。

初学者の間は、ソース中の変数名や表示内容を英数字中心にしてください。日本語を使うと、NetCOBOLとGnuCOBOL、UTF-8とShift_JISの違いが一気に絡んできます。

###コンパイルして実行する

MSYS2 UCRT64で作業フォルダへ移動します。

cd /c/cobol-work

コンパイルします。

cobc -x --fixed -std=cobol85 -o HELLO.exe HELLO.COB
各オプションの意味は次のとおりです。

-x             実行可能ファイルを作る
--fixed        固定形式として読み込む
-std=cobol85   COBOL 85に近い文法でチェックする
-o HELLO.exe   出力するファイル名

GnuCOBOLの-std=cobol85は、ベンダー独自拡張をできるだけ使わず、複数のCOBOLコンパイラで通りやすいソースを書く練習に向いています。

実行します。
./HELLO.exe


###コマンドプロンプトから使えるようにする

現場の「DOS」に近づけるため、次はMSYS2の画面ではなく、Windowsのコマンドプロンプトから実行します。
C:\cobol-workに次のファイルを作ります。
BUILD.CMD
内容は以下です。

@echo off
setlocal

set "PATH=C:\msys64\ucrt64\bin;%PATH%"
cd /d C:\cobol-work

echo COBOL program is compiling...

cobc -x --fixed -std=cobol85 -o HELLO.exe HELLO.COB

if errorlevel 1 (
    echo.
    echo BUILD ERROR
    exit /b 1
)

echo.
echo BUILD SUCCESS
echo.

HELLO.exe

endlocal

コマンドプロンプトで実行します。
cd /d C:\cobol-work
BUILD.CMD

これで、

COBOLソースをコンパイルする
エラーがあれば中断する
成功したら実行する

という、業務のバッチ処理に近い流れを体験できます。

###入出力ファイルを使うバッチ処理

料金管理システムでは、画面操作だけでなく、

入力ファイルを読む
↓
料金を計算する
↓
結果ファイルを出す

というバッチ処理が出てくる可能性があります。

たとえば、プログラムに入力を渡して結果をファイルへ保存する場合は次のようにします。

HELLO.exe < INPUT.TXT > OUTPUT.TXT

意味は、

< INPUT.TXT    INPUT.TXTを標準入力として渡す
> OUTPUT.TXT   出力をOUTPUT.TXTへ書き込む

です。

出力結果を表示するには、

type OUTPUT.TXT

とします。
これらをまとめたRUN.CMDは、たとえば次のように書けます。

@echo off
setlocal

set "PATH=C:\msys64\ucrt64\bin;%PATH%"
cd /d C:\cobol-work

cobc -x --fixed -std=cobol85 -o HELLO.exe HELLO.COB

if errorlevel 1 (
    echo BUILD ERROR
    exit /b 1
)

HELLO.exe < INPUT.TXT > OUTPUT.TXT

type OUTPUT.TXT

endlocal

コマンドプロンプトとバッチファイルによる自動処理は、現在のWindowsでも正式にサポートされている仕組みです。
